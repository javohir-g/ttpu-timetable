## Что это

Бот подключается к `ttpu.edupage.org`, сам разбирает расписание и отдаёт его
студентам и преподавателям TTPU в Telegram — без единой сторонней библиотеки,
только стандартная библиотека Python.

Два режима в одном репозитории:

| Файл | Назначение |
|---|---|
| `universal_bot.py` | **Основной бот.** Любой студент или преподаватель настраивает себя сам через `/start`. Живёт на Railway. |
| `bot.py` | Разовая отправка расписания одной группы в конкретный чат — для cron/Task Scheduler. |

## Возможности

- 🎓 **Самостоятельная настройка** — студент выбирает направление и группу, преподаватель ищется по фамилии
- 📅 **`/today` · `/tomorrow` · `/week`** с навигацией по дням и цветовой маркировкой типа пары
- 🔔 **Напоминания** перед началом пары — 5/10/15/30/60 минут, по часовому поясу Ташкента
- 📱 **Мини-апп** в том же процессе: веб-версия расписания с кнопкой в меню бота
- 🧵 **Одно сообщение на диалог** — бот редактирует текущий экран, а не засоряет чат новыми сообщениями на каждый шаг
- 🪶 **Zero dependencies** — весь бот на `urllib`/`http.server` из стандартной библиотеки

## Команды

| Команда | Что делает |
|---|---|
| `/start` | Выбор роли: студент (направление → группа) или преподаватель (поиск по фамилии) |
| `/today` | Расписание на сегодня |
| `/tomorrow` | Расписание на завтра |
| `/week` | Вся неделя, по дням в сворачиваемых блоках |
| `/remind` | Включить/выключить напоминания и выбрать время |
| `/change` | Сменить группу или преподавателя |
| `/help` | Список команд |

## Быстрый старт

```bash
git clone https://github.com/javohir-g/ttpu-timetable.git
cd ttpu-timetable
cp config.example.json config.json
# впишите telegram_bot_token от @BotFather
python universal_bot.py
```

Бот работает long polling, пока запущен процесс. Настройки пользователей
сохраняются в `users.json` и переживают перезапуск.

<details>
<summary>Автозапуск при старте Windows</summary>

```
schtasks /Create /TN "EdupageBot" /TR "pythonw \"<путь>\universal_bot.py\"" /SC ONSTART
```
</details>

## Напоминания о парах

Бот пишет перед началом пары — время выбирает сам пользователь командой
`/remind` (5, 10, 15, 30 или 60 минут, по умолчанию выключено).

Проверка времени живёт в главном цикле бота, который просыпается не реже
чем раз в 50 секунд — отдельный планировщик не нужен. Время считается в
поясе Ташкента (UTC+5, без перехода на летнее/зимнее), а не по часам машины:
на хостинге в другом поясе напоминания иначе уехали бы на часы.

Пропущенное не догоняется: если бот лежал, напоминание о паре, которая уже
идёт, только сбивало бы с толку.

## Мини-апп

Тот же процесс поднимает веб-сервер на порту из переменной `PORT` (её задаёт
хостинг) и отдаёт папку `miniapp/`. Страница, данные и service worker уходят
с заголовком `no-cache`, иначе обновление не доехало бы до телефона; иконки
и анимации кэшируются на сутки.

Расписание (`miniapp/data.json`) пересобирается тем же сборщиком, что и в
сборках GitHub: сразу при запуске (свежий контейнер иначе отдал бы файл из
репозитория, которому может быть несколько дней) и дальше раз в
`DATA_REFRESH_MIN` минут.

Публикация на **GitHub Pages** остаётся запасным адресом — обновляется своим
расписанием раз в шесть часов и ничего не ломает, если основной хостинг
недоступен.

## Деплой на Railway

Напоминания приходят только пока бот запущен, поэтому он живёт на Railway,
а не на домашнем компьютере.

1. **Источник** — этот репозиторий, ветка `main`. Сборщик подхватит
   `requirements.txt` и `railway.json` (команда запуска уже прописана).
2. **Том (Volume)** — подключить к сервису с путём `/data`. Без него
   файловая система очищается при каждом развёртывании, и список
   пользователей вместе с настройками напоминаний пропадёт.
3. **Домен** — Settings → Networking → Generate Domain. Тот же сервис
   раздаёт мини-апп, поэтому домен нужен и идёт в `MINIAPP_URL`.
4. **Переменные окружения:**

   | Переменная | Значение | Обязательна |
   |---|---|---|
   | `TELEGRAM_BOT_TOKEN` | токен от [@BotFather](https://t.me/BotFather) | ✅ |
   | `DATA_DIR` | `/data` | ✅ |
   | `MINIAPP_URL` | выданный домен, например `https://example.up.railway.app/` | желательно |
   | `EDUPAGE_SUBDOMAIN` | `ttpu` (значение по умолчанию) | нет |
   | `DATA_REFRESH_MIN` | как часто пересобирать расписание, минут (по умолчанию `30`) | нет |
   | `SERVE_MINIAPP` | `0`, если мини-апп раздаёт кто-то другой | нет |

Токен в репозиторий не кладём: `config.json` в `.gitignore`, на хостинге
настройки берутся из переменных окружения (`load_config()` в
`universal_bot.py` сначала смотрит в `os.environ`, потом в `config.json`).

> ⚠️ Telegram разрешает опрашивать обновления только одному процессу. Если
> бот запущен и на Railway, и локально (или на двух Railway-проектах сразу),
> оба получат `409 Conflict` — лишний нужно остановить.

## bot.py — разовая отправка

Для ежедневной авторассылки одной группе в фиксированный чат: заполни
`class_name`, `telegram_bot_token`, `telegram_chat_id` в `config.json` и:

```bash
python bot.py today          # сегодня
python bot.py tomorrow       # завтра
python bot.py week           # неделя
python bot.py --dry-run week # в консоль, без отправки
```

Ежедневно в 7:00 через планировщик:

```
schtasks /Create /TN "EdupageTimetable" /TR "python \"<путь>\bot.py\" today" /SC DAILY /ST 07:00
```

## Структура проекта

```
edupage-telegram-bot/
├── universal_bot.py     # основной бот + веб-сервер мини-аппа
├── bot.py               # разовая отправка расписания
├── config.json          # токен и настройки (не в git)
├── config.example.json  # шаблон конфига
├── railway.json         # команда запуска для Railway
├── miniapp/
│   ├── index.html       # веб-версия расписания
│   ├── build_data.py    # сборщик data.json из edupage
│   └── data.json         # собранное расписание (генерируется)
└── .github/workflows/
    └── deploy.yml        # запасная публикация на GitHub Pages
```

## Технические детали

<details>
<summary>Почему резолвер переключён на IPv4</summary>

У `ttpu.edupage.org` есть адрес IPv6, и на серверах без маршрута к нему
(встречалось на хостинге сборок GitHub) запрос зависает и падает по тайм-
ауту. Импорт сборщика (`build_data`) переключает резолвер на IPv4 — для
Telegram и остального это ничего не меняет.
</details>

<details>
<summary>Почему одно сообщение, а не поток новых</summary>

Пошаговая настройка, расписание и меню напоминаний редактируют одно и то же
сообщение (`ScheduleBot.show()`), а не шлют новое на каждый шаг. При нажатии
кнопки бот редактирует точно то сообщение, на котором она висит — надёжнее,
чем держать id в памяти, которая не переживает перезапуск. Клавиатура в
`editMessageText` передаётся явно всегда, в том числе пустая, — иначе
Telegram оставляет кнопки от предыдущего экрана висеть под новым текстом.
</details>

<details>
<summary>Кэш расписания</summary>

Данные с edupage кэшируются 30 минут (`CACHE_TTL`) внутри процесса бота —
свежая неделя подхватывается автоматически без перезапуска.
</details>
